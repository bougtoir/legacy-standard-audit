# Final TFSC revision plan

## Scope and invariants

This pass revises the existing frozen project. It does not restart case selection, replace inconvenient cases, or infer stronger evidence than the registered sources support.

The following are fixed:

- the 122-candidate, 12-domain universe;
- the seven-case set frozen at `2026-09-24T09:55:00Z`;
- case roles and selection scores;
- registered numerical inputs and their checksums;
- the distinction among historical, current frictionless, and transition-adjusted optima;
- retention of null and insufficient-evidence cases;
- prohibition on pooling case-specific effect magnitudes.

## Permitted change classes

### Manuscript-only changes

- narrow the title and central claim;
- strengthen the theoretical bridge among standards, technological capability, path dependence, and transition governance;
- distinguish a re-audit trigger from a redesign recommendation;
- foreground oracle/proxy limitations beside the relevant results;
- describe heterogeneity as a portability test rather than a basis for population inference;
- correct language, citations, captions, and file organization.

These changes cannot alter analytical values or frozen classifications unless a reproducibility defect is discovered and corrected through the canonical pipeline.

### Frozen-data analyses

- recompute existing case outputs from registered snapshots;
- run leave-one-case/domain and strongest-case-removal checks;
- run supported threshold, source-quality, and alternate-loss sensitivities;
- derive symbolic or native-unit break-even thresholds from existing outputs;
- redesign cross-case presentation without pooling incommensurate magnitudes.

All added numerical results must be generated by code and enter `MANUSCRIPT_VALUES.csv`.

### Legitimate new external transition evidence

New public sources may be registered only to evaluate implementation, switching, maintenance, communication, metering, useful-life, discount, safety, or regulatory constraints for the four primary cases. Each source must have provenance, an immutable local snapshot where redistribution permits, size, SHA-256, access time, and a compatibility judgment.

Evidence is classified:

- **A** — case-compatible empirical transition evidence; numerical transition-adjusted estimation may be attempted;
- **B** — credible but insufficiently case-specific; only threshold or break-even analysis is permitted;
- **C** — weak or non-comparable; transition-adjusted status remains unidentified.

### Prohibited post-hoc changes

- replacing a frozen case because its result is null, weak, contrary, or inconvenient;
- changing selection scores using observed results;
- introducing an unregistered data source into an analysis;
- imputing a transition-cost point estimate from non-comparable evidence;
- monetizing comfort, safety, reliability, crop yield, or welfare without applicable valuation evidence;
- relabeling an oracle/proxy result as a realized deployment effect;
- pooling effect magnitudes with different objectives or units;
- claiming the incumbent was historically optimal unless identified;
- editing tests merely to ratify a desired result;
- manually transcribing revised analytical values into the manuscript generator.

## Decision priorities

1. Correct scientific overstatement before improving presentation.
2. Preserve negative and unidentified conclusions.
3. Prefer a transparent evidence gate to a speculative transition estimate.
4. Keep the paper's novelty procedural and governance-oriented unless direct antecedent review supports more.
5. Make every claim auditable from registered evidence or generated output.

## Acceptance gate

The revision is complete only after all R0–R13 outputs exist, the canonical build and integrity checks pass from registered inputs, current TFSC requirements are rechecked, six hostile reviews are resolved, author-only declarations are isolated, a reviewed PR is merged, and the public repository is synchronized.
